# hass485 자동 재시작 가이드

## 개선사항

### 1. 프로그램 레벨 자동 재시작
- `main.go`에 무한 재시작 루프 추가
- **2개 이상의 컨트롤러에서 오류가 발생하면 전체 프로그램 재시작** (개선됨)
- **60초 대기 후 자동 재시작** (개선됨)

### 2. MQTT 연결 강화
모든 컨트롤러(조명, 보일러, 엘리베이터, 도어벨)에 다음 개선사항 적용:

#### 무한 재연결 시도
- MQTT 브로커 연결 실패 시 **15초 대기 후 재시도** (개선됨)
- 연결 성공할 때까지 무한 반복

#### 연결 상태 모니터링
- 30초마다 MQTT 연결 상태 확인
- 연결이 끊어지면 자동 재연결 시도
- 재연결 후 구독 자동 복원
- **Keep-Alive 간격: 60초, Ping 타임아웃: 20초, 연결 타임아웃: 60초** (개선됨)

### 3. HA 재부팅 대응 강화
**Home Assistant 재부팅 후 MQTT 장치 인식 문제 해결:**

#### 정기적인 상태 발행 (Heartbeat)
- **5분마다 모든 장치의 현재 상태를 MQTT로 발행**
- HA가 재부팅되어도 장치가 살아있음을 지속적으로 알림
- 조명, 보일러, 엘리베이터, 도어벨 모든 컨트롤러에 적용

#### MQTT 연결 복구 시 즉시 상태 발행
- MQTT 연결이 복구될 때마다 즉시 초기 상태 발행
- HA 재부팅 후 MQTT 재연결 시 장치를 즉시 인식 가능

#### 강화된 에러 처리
- 패닉 복구 메커니즘
- 연결 끊김/복구 핸들러
- 안전한 nil 체크

### 4. 시스템 레벨 자동 재시작

#### Linux용 스크립트 (`restart_wrapper.sh`)
```bash
chmod +x restart_wrapper.sh
./restart_wrapper.sh
```

#### Windows용 배치 파일 (`restart_wrapper.bat`)
```cmd
restart_wrapper.bat
```

## 로그 확인

### 프로그램 로그
- 모든 컨트롤러의 연결 상태와 오류가 콘솔에 출력됩니다
- MQTT 연결/재연결 상태를 실시간으로 확인 가능

### 재시작 래퍼 로그
- `hass485_restart.log` 파일에 재시작 이력이 기록됩니다
- 언제, 몇 번 재시작되었는지 확인 가능

## 문제 해결

### MQTT 연결 문제
1. 브로커 주소 확인: `tcp://192.168.0.15:1883`
2. 네트워크 연결 상태 확인
3. 브로커 서비스 상태 확인
4. **연결 타임아웃이 길어졌으므로 네트워크 불안정 시에도 더 안정적으로 동작**

### 재시작 빈도 문제
1. **재시작 간격이 60초로 증가하여 빈번한 재시작 방지**
2. **2개 이상의 컨트롤러 오류 시에만 전체 재시작**
3. 개별 컨트롤러 오류는 독립적으로 처리

### HA 재부팅 후 장치 인식 문제
1. **5분마다 정기적인 상태 발행으로 HA가 장치를 지속적으로 인식**
2. **MQTT 연결 복구 시 즉시 상태 발행으로 빠른 복구**
3. **모든 컨트롤러(조명, 보일러, 엘리베이터, 도어벨)에 적용**

### 시리얼 포트 문제
1. 포트 권한 확인 (Linux: `/dev/ttyUSB*`)
2. USB-RS485 어댑터 연결 상태 확인
3. 포트 번호 설정 확인

### 자동 재시작이 작동하지 않는 경우
1. 래퍼 스크립트 실행 권한 확인
2. 로그 파일 확인
3. **정상 종료(종료 코드 0)인지 확인** (무제한 재시작이므로 수동 중단 필요)

## 설정 변경

### 재시작 간격 변경
- `main.go`: `time.Sleep(60 * time.Second)` 수정
- 래퍼 스크립트: `sleep 60` 또는 `timeout /t 60` 수정

### 최대 재시작 횟수 변경
- 래퍼 스크립트: **무제한 재시작** (최대 횟수 제한 제거됨)

### MQTT 브로커 주소 변경
- `main.go`: `mqttBroker := "tcp://192.168.0.15:1883"` 수정
