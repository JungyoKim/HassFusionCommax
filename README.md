# HassFusionCommax

HassFusionCommax는 홈어시스턴트(Home Assistant)와 코맥스(Commax) 스마트홈 월패드 시스템 간의 통합을 위해 설계된 하이브리드 브릿지 시스템입니다. 이 프로젝트는 단순한 RS485 통신을 넘어서, 월패드의 내부망 HTTP 통신, SOAP API, 그리고 물리적 시리얼 라인을 복합적으로 엮어내는 아키텍처를 가지고 있습니다.

이를 통해 홈어시스턴트에서 조명, 보일러 제어뿐만 아니라 주차 알림, 엘리베이터 상태, 에너지 사용량(시간별/일별/월별/연별)까지 실시간으로 파악할 수 있도록 구성되어 있습니다.

## 🏗️ 시스템 아키텍처

프로젝트는 **Go 기반의 백엔드 데몬**과 **Python 기반의 홈어시스턴트 통합 모듈(Custom Component)** 두 가지로 분리되어 있습니다.

1. **Go 데몬 (`hassfusion/`)**: 하드웨어 포트를 직접 점유하고 네트워크 패킷을 수집합니다. 통신 병목 현상을 해결하기 위해 각 컨트롤러는 별도의 Go 루틴으로 격리되며 메세지는 WebSocket을 통해 HA로 중계됩니다.
2. **HA Custom Component (`custom_components/hassfusion/`)**: 데몬과 WebSocket으로 상시 통신하며 단일 소켓 위에서 Event 구독 기반으로 HA 엔티티(센서, 스위치, 온도조절기 등)를 갱신합니다.

## 📡 장치별 통신 프로토콜 상세 안내

이 프로젝트는 다음과 같은 세 가지 방식을 혼합하여 데이터를 취득합니다. (1) **RS485 시리얼 통신**, (2) **월패드 내부 SOAP API 폴링**, (3) **TCP 패킷 스니핑/어셈블리**.

### 1. 조명 (Light) - `RS485`
조명 제어 및 상태 확인은 지정된 RS485 채널을 통해 이루어집니다. 패킷은 앞쪽부터 헤더, 기기 주소 파트, 명령 파트, 체크섬으로 이루어져 있습니다.

- **조회 명령 (Polling)**: `3001000000000031` (1번 조명 조회) ~ `3005000000000035` (5번 조명 조회)
- **상태 응답**: 월패드 측에서 `B001...` (켜짐) 또는 `B000...` (꺼짐) 패턴으로 응답.
- **제어 명령 (ON)**: `3101010000000033` (1번 ON) ~ `3105010000000037`
- **제어 명령 (OFF)**: `3101000000000032` (1번 OFF) ~ `3105000000000036`

### 2. 보일러 (Climate) - `RS485`
방별 난방 설정 온도와 현재 온도를 조절합니다. 온도 값은 통신상에서 BCD(Binary-Coded Decimal) 포맷을 이용합니다. 보일러 제어 패킷의 끝에는 단순 덧셈 방식의 조잡한 체크섬이 사용됩니다. (이전 7바이트를 모두 더한 값의 하위 1바이트)

- **조회 명령**: `0201000000000003` (1번 방) ~ `0204000000000006`
- **상태 응답**: `0x82` 또는 `0x84`로 시작하는 8바이트 패킷.
  - Byte[1]: 상태 모드 (`0x81`, `0x83`은 켜짐 모드)
  - Byte[2]: 방 번호 (1~4)
  - Byte[3]: 현재 온도 (BCD 포맷, 예: 23도 -> 보낼 때는 십진수 분할 변환)
  - Byte[4]: 설정 희망 온도 (BCD)
- **제어 로직 (모드 설정)**: `0x04` 명령어 코드와 함께 `0x81`(Heat) 또는 `0x00`(Off) 전송.
- **제어 로직 (온도 설정)**: `0x03` 명령어 코드와 조작할 BCD 온도값 결합 전송. 보낼 때의 구조는 `[0x04, 방번호, 0x03, 온도, 0x00, 0x00, 0x00, 체크섬]` 형태.

### 3. 일괄소등 및 엘리베이터 호출 스위치 - `RS485`
외출 시나리오를 위한 월패드 연동 스위치입니다. 동일 RS485 버스를 사용합니다.

- **상태 조회**: `2001000000000021`
- **응답 판별**: 패킷이 `0xA00101`로 시작하면 켜짐, `0xA00100`이면 꺼짐 상태.
- **제어 명령 (ON/OFF)**: 일괄소등 ON은 `2201010100000025`, OFF는 `2201000100000024`.
- **엘리베이터 하드웨어 버튼 호출**: `A0010100081500BF` (센서 동작이 아닌 단순히 하드웨어 스위치를 릴레이하는 단방향 패킷)

### 4. 현관 도어벨 - `RS485`
누군가 현관에서 초인종을 눌렀을 때만 발생하는 불규칙적인 이벤트성 패킷을 감지합니다. 이 채널은 버퍼 분할(Fragmentation) 리스크가 크기 때문에 패턴 서칭 방식을 씁니다.

- **호출 감지(벨울림)**: 
  - `02100202090302020903100000004003` 또는 `02100109120101091201100000005A03` 패턴이 버퍼에 감지되면 벨이 울린 것으로 판정. 
  - 감지되면 WebSocket으로 즉시 `on` 상태를 뿌리고, 5초 후 자체적으로 `off` 이벤트를 발생시킵니다.
- **공동현관 문열림 (Command)**: `02110202090302020903054000017703` 패킷 전송.

### 5. 엘리베이터 상태 모니터 뷰어 - `HTTP SOAP 통신`
엘리베이터의 실시간 층수와 상/하행 이동 이벤트를 파악합니다. 하드웨어 RS485 라인이 아닌 단지 내 관리 서버(CES)의 API를 직접 호출(Polling)합니다.

- **Endpoint**: `http://월패드IP:29715`
- **Payload**: `urn:ces#getEvStatus` XML Body를 담아 POST 요청.
- **Parsing**: 반환된 XML의 `<item>` 트리 내의 `carFloor`(층), `isBasement`(지하 여부), `carDirection`(방향, 1:상행/2:하행/0:정지), `evStatus`(동작상태) 값들을 분해하여 변화 발생 시에만 HA로 쏴줍니다.
- 아파트 서버에 무리를 주지 않도록 엘리베이터가 움직일 땐 3초, 모두 멈춰있을 때는 5~10초로 폴링 주기를 가변합니다.

### 6. 에너지 사용 정보 (전기, 가스, 수돗물) - `HTTP SOAP 통신`
- **Endpoint**: `http://월패드IP/ces/ces.php`
- 월패드의 고유 MAC과 호수/동 정보를 `callEDS` SOAP 명령으로 싸서 POST 방식으로 요청합니다.
- `proc_get_energy_annual_select`, `proc_get_daily_energy`, `proc_get_hour_energy` 스토어드 프로시저를 직접 호출.
- 결과값 구조: `날짜(시간)#사용량$` 방식으로 이어져 있으며 정규식(`<result>`)을 통해 데이터를 추출한 후 `,` 단위로 폭파시켜 12가지 항목(3종류 유틸리티의 월/년/일/시 누적치)을 얻어냅니다. 이를 위해 Go 데몬 내 메모리에 마지막 상태값을 상시 캐싱해둡니다(재시작 시 즉각적인 값 복원 위함).

### 7. 주차 관리 알림 - `TCP 패킷 스니핑/어셈블리`
주차장 출입 차량 알림은 사용자가 조작하여 당겨오는(Polling) 값이 아닙니다. 외부 시스템에서 월패드로 비정기적으로 꽂아주는 데이터이므로 TCP 패킷 스니핑을 통해 `parkService` 패킷을 인터셉트(Intercept) 합니다.

- `tcpdump` 또는 공유기 네트워크 미러링 환경에서 `gopacket/tcpassembly`를 이용해 Raw 패킷들을 완벽한 HTTP XML 문서로 조립합니다.
- 조립된 HTTP Body 내에 `<parkService>` 트리 구조가 감지되면 `<time>`, `<type>`(1:입차/2:출차), `<carNo>`(차량번호) 값을 파싱합니다.
- 파싱 실패로 인한 메모리 누수 방지 로직과 동시성 채널 맵핑 로직이 포함되어 있습니다.

## 🚀 설치 및 컴파일 안내

### 1. Go 데몬 브릿지 컴파일 및 실행
이 프로젝트는 Windows나 Linux 바이너리를 직접 빌드하여 사용하도록 고안되었습니다.
```bash
cd hassfusion

# 환경에 맞는 빌드 명령어 사용 (예: 라즈베리파이나 리눅스)
env GOOS=linux GOARCH=amd64 go build -o hassfusion_linux_amd64 main.go

# 실행
./hassfusion_linux_amd64 -config config.yaml
```
RS485가 사용하는 시리얼 주소 공간 체계는 시스템 환경마다 다르므로 실행 환경에 맞게 `config.yaml` 포트 값을 반드시 알맞게 적어주어야 합니다 (`/dev/ttyUSBX`).

### 2. Home Assistant Custom Component 등록
1. 본 리포지토리의 `custom_components/hassfusion` 디렉토리를 통째로 복사해서 홈어시스턴트 쪽 `config/custom_components/` 경로 안에 넣습니다.
2. 홈어시스턴트를 리부팅합니다.
3. [기기 및 서비스] 설정에서 'HassFusion' 커스텀 통합을 추가하고, 앞서 데몬이 떠 있는(혹은 브릿지로 쓸) IP 주소와 지정 포트를 입력합니다.
4. 즉시 모든 장치 목록(보일러 N개, 조명 N개, 센서 N개 등)이 등록됩니다.
