# HassFusionCommax

HassFusionCommax는 홈어시스턴트(Home Assistant)와 코맥스(Commax) 스마트홈 월패드 시스템 간의 통합을 위해 설계된 하이브리드 브릿지 시스템입니다. 이 프로젝트는 단순한 RS485 통신을 넘어서, 월패드의 내부망 HTTP 통신, SOAP API, 그리고 물리적 시리얼 라인을 복합적으로 엮어내는 아키텍처를 가지고 있습니다.

이를 통해 홈어시스턴트에서 조명, 보일러 제어뿐만 아니라 주차 알림, 엘리베이터 상태, 에너지 사용량(시간별/일별/월별/연별)까지 실시간으로 파악할 수 있도록 구성되어 있습니다.

## 🏗️ 시스템 아키텍처

프로젝트는 **Go 기반의 백엔드 데몬**과 **Python 기반의 홈어시스턴트 통합 모듈(Custom Component)** 두 가지로 분리되어 있습니다.

1. **Go 데몬 (`hassfusion/`)**: 하드웨어 포트를 직접 점유하고 네트워크 패킷을 수집합니다. 통신 병목 현상을 해결하기 위해 각 컨트롤러는 별도의 Go 루틴으로 격리되며 메세지는 WebSocket을 통해 HA로 중계됩니다.
2. **HA Custom Component (`custom_components/hassfusion/`)**: 데몬과 WebSocket으로 상시 통신하며 단일 소켓 위에서 Event 구독 기반으로 HA 엔티티(센서, 스위치, 온도조절기 등)를 갱신합니다.

---

## 📡 장치별 통신 프로토콜 상세 안내

이 프로젝트는 (1) **RS485 시리얼 통신**, (2) **월패드 내부 SOAP API 폴링**, (3) **TCP 패킷 스니핑/어셈블리** 세 가지 방식을 혼합하여 데이터를 취득합니다. 아래 표는 각각의 통신 규격과 하드웨어 제어 논리를 설명합니다.

### 1. 조명 (Light) - `RS485`
조명 제어 및 상태 확인은 지정된 RS485 채널을 통해 이루어집니다. 패킷은 `[헤더] + [기기/장치번호] + [명령어] + [체크섬]` 구조를 갖습니다.

| 기능 (Function) | 설명 (Description) | 프로토콜 / 패킷 구조 (Hex) |
| :--- | :--- | :--- |
| **상태 조회 (Poll)** | 1~5번 조명의 현재 상태를 월패드에 질의 | `30 01 00 00 00 00 00 31` ~ `30 05 00 00 00 00 00 35` |
| **상태 응답 (Ack)** | 월패드가 반환하는 조명 켜짐/꺼짐 상태 | `B0 01 ...` (켜짐) / `B0 00 ...` (꺼짐) |
| **제어 전송 (ON)** | 특정 번호의 조명 켜기 | `31 01 01 00 00 00 00 33` ~ `31 05 01 00 00 00 00 37` |
| **제어 전송 (OFF)** | 특정 번호의 조명 끄기 | `31 01 00 00 00 00 00 32` ~ `31 05 00 00 00 00 00 36` |

### 2. 보일러 (Climate) - `RS485`
각 방의 난방 설정 온도와 현재 온도를 조절합니다. 온도 값은 통신상에서 BCD(Binary-Coded Decimal) 포맷을 이용합니다. 체크섬은 앞선 7바이트의 단순 합산(Sum)의 하위 1바이트입니다.

| 기능 (Function) | 설명 (Description) | 프로토콜 / 패킷 구조 (Hex) |
| :--- | :--- | :--- |
| **상태 조회 (Poll)** | 1~4번 방의 난방 상태 확인 | `02 01 00 00 00 00 00 03` ~ `02 04 00 00 00 00 00 06` |
| **상태 응답 (Ack)** | `[1Byte: 상태][2Byte: 방번호][3Byte: 현재온도][4Byte: 희망온도]`로 응답 | `82 81 01 23 25 ...` (`0x81/0x83`: 켜짐, `23`/`25`는 BCD 온도) |
| **모드 설정 (Mode)** | 보일러 켜기(Heat) 또는 끄기(Off) | `[04, 방번호, 04, 모드(81/00), 00, 00, 00, 합산CS]` |
| **온도 설정 (Temp)** | 희망 난방 온도 설정 변경 (BCD 인코딩 변환 필수) | `[04, 방번호, 03, 온도(BCD), 00, 00, 00, 합산CS]` |

### 3. 일괄소등 및 엘리베이터 호출 스위치 - `RS485`
동일한 RS485 버스를 사용하며, 외출 시나리오 버튼 릴레이를 담당합니다.

| 기능 (Function) | 설명 (Description) | 프로토콜 / 패킷 구조 (Hex) |
| :--- | :--- | :--- |
| **일괄소등 조회** | 현재 집안 전체 소등 상태 확인 | `20 01 00 00 00 00 00 21` |
| **일괄소등 응답** | 상태 여부 반환 | `A0 01 01 ...` (켜짐) / `A0 01 00 ...` (꺼짐) |
| **일괄소등 ON** | 일괄소등 활성화 명령 | `22 01 01 01 00 00 00 25` |
| **일괄소등 OFF** | 일괄소등 해제 명령 | `22 01 00 01 00 00 00 24` |
| **엘리베이터 호출** | 하드웨어 스위치를 통한 엘리베이터 단방향 호출 | `A0 01 01 00 08 15 00 BF` |

### 4. 현관 도어벨 - `RS485`
누군가 현관에서 초인종을 눌렀을 때만 발생하는 이벤트성 패킷입니다. 버퍼 분할(Fragmentation) 리스크 대응을 위해 특정 Hex 패턴 매칭 방식을 사용합니다.

| 기능 (Function) | 설명 (Description) | 패턴 매칭 및 명령 (Hex) |
| :--- | :--- | :--- |
| **벨 호출 감지 (Ring)** | 초인종 누름 감지 시 HA로 이벤트 트리거 (5초 유지) | `02 10 02 02 09 03 02 02 09 03 ... 40 03` 또는 `02 10 01 09 ... 5A 03` |
| **공동현관 문열림** | 외부에서 방문자 확인 후 1층 출입문 개방 | `02 11 02 02 09 03 02 02 09 03 05 40 00 01 77 03` |

### 5. 공동현관 로비폰 문열림 - `HTTP SOAP 통신`
지하 주차장(B4, B3) 및 1층 로비의 공동현관 방문객 확인 후 문을 열어주는 제어 프로토콜입니다. RS485가 아닌 각 층의 로비폰 IP로 직접 SOAP 요청을 쏩니다.

| 기능 (Function) | 설명 (Description) | 엔드포인트 및 Payload |
| :--- | :--- | :--- |
| **로비 문열림** | 지정된 층의 공동현관문 개방 명령 전송 (POST) | `Endpoint`: `http://[각_층_로비폰_IP]:29752/`<br>`Payload`: `<n0:setOutOfBandDoorOpen ...><in>15</in></n0:setOutOfBandDoorOpen>` |

### 6. 엘리베이터 상태 모니터 - `HTTP SOAP 통신`
하드웨어 라인이 아닌 아파트 단지 관리 서버(CES)의 내부 API를 주기적으로 폴링(Polling)합니다. 부하 조절을 위해 엘리베이터 이동중에는 3초, 정지 중에는 10초 주기로 변경됩니다.

| 항목 | 상세 규격 (Details) |
| :--- | :--- |
| **Endpoint** | `http://[월패드_IP]:29715` |
| **Payload (XML)** | `urn:ces#getEvStatus` SOAP 형식의 바디 전송 (POST) |
| **Parsing 구조** | 반환 XML 중 `<item>` 트리 파싱:<br>- `carFloor`: 현재 위치(층)<br>- `carDirection`: 이동 방향 (`1`:상행, `2`:하행, `0`:정지)<br>- `isBasement`: 지하 여부 |

### 7. 에너지 사용 정보 (전기, 가스, 수돗물) - `HTTP SOAP 통신`
월패드 IP를 통해 단지 서버에 10분마다 쿼리를 날려 12가지 사용량 데이터를 추출합니다. 데몬 내부 구조(RWMutex)를 통해 데이터를 캐싱하여 HA 재시작 시 즉각 응답합니다.

| 항목 | 상세 규격 (Details) |
| :--- | :--- |
| **Endpoint** | `http://[월패드_IP]/ces/ces.php` |
| **Payload (XML)** | `callEDS` 명령에 월패드 MAC 주소, 기기 1ID, 동/호수를 포함하여 조립 |
| **수집 프로시저** | - `proc_get_energy_annual_select` (이번 달 및 올해 연간 유틸리티 사용량 추출용)<br>- `proc_get_daily_energy` (금일 사용량)<br>- `proc_get_hour_energy` (현재 시간 사용량) |
| **Parsing 로직** | 아파트 서버가 정규 구조를 어기는 경우를 대비해 정규식(`(?s)<(?:\w+:)?result[^>]*>(.*?)</(?:\w+:)?result>`) 기반으로 본문만 적출 후 `날짜#측정값$` 포맷 스플릿 파싱 |

### 8. 주차 관리 알림 - `TCP 패킷 스니핑`
차량 입차/출차 이벤트는 폴링(Polling)이 불가하며, 외부 시스템에서 월패드로 비정기적으로 푸시(Push)하는 데이터입니다. 따라서 라우터 캡처 환경을 구축해 `tcpassembly` 기술로 실시간 방화벽 패킷 스니핑을 수행합니다.

| 항목 | 상세 규격 (Details) |
| :--- | :--- |
| **패킷 조립기 (Assembler)** | `gopacket`을 사용해 TCP 시퀀스를 재조립(Reassembly)하여 완전한 형태의 HTTP Request/Response를 생성함. (1MB 초과 시 OOM 방지 버퍼 클리어 알고리즘 내장) |
| **타겟 탐지** | HTTP Body 내부에서 `<parkService>` 트리 구조 감지 |
| **Parsing 데이터 추출** | - `<type>` (`1`: 입차, `2`: 출차) <br>- `<carNo>` (차량 번호, 예: '12가3456')<br>- `<time>` (발생 시각) |

## 🚀 설치 및 컴파일 안내

### 1. Go 데몬 브릿지 컴파일 및 실행
이 프로젝트는 Windows나 Linux 바이너리를 직접 빌드하여 사용하도록 고안되었습니다.

```bash
cd hassfusion

# 환경에 맞는 빌드 명령어 사용 (예: 라즈베리파이나 리눅스)
env GOOS=linux GOARCH=amd64 go build -o hassfusion_linux_amd64 main.go

# 실행
./hassfusion_linux_amd64 -config config.yaml
```
RS485가 사용하는 시리얼 주소 공간 체계는 시스템 환경마다 다르므로 실행 환경에 맞게 `config.yaml` 포트 값을 반드시 알맞게 적어주어야 합니다 (`/dev/ttyUSB0` 등).

### 2. Home Assistant Custom Component 등록
1. 본 리포지토리의 `custom_components/hassfusion` 디렉토리를 통째로 복사해서 홈어시스턴트 쪽 `config/custom_components/` 경로 안에 넣습니다.
2. 홈어시스턴트를 리보팅합니다.
3. [설정] > [기기 및 서비스] 통합 메뉴에서 **HassFusion**을 검색 후 추가합니다.
4. 데몬이 떠 있는(혹은 브릿지로 쓸) IP 주소와 지정 포트를 입력하면 즉시 통신을 성립하여 모든 하드웨어 장치 엔티티 목록이 홈어시스턴트에 등록됩니다.
